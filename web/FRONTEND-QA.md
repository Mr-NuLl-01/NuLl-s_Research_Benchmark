# V2 第一轮网页实现与核验

日期：2026-10-23。当前协议：`nrb-auto-report-v2` / `2.0.0-rc.1`。

## 已实现

- 20 题当前目录：8 道 Python 已开放、12 道第二轮计划。原 21 题保持历史入口，原题文件不改写。
- 题目详情、报告导入、记录详情均有明确返回入口；题库搜索与筛选在详情返回后保留。
- 题目和验证器下载只使用已登记的 Google Drive HTTPS 资源。站内题面只读；私有 Drive 文件不通过浏览器跨域抓取。
- Python 不设人工分输入。上传报告后核对版本、种子、题包、验证器和检查清单；按站点白名单重算权重和分数。
- 拒绝删减、重复或未知检查、篡改权重、错误汇总、错误指纹、非法结果类型。存在未执行检查时得分为 null；已执行全部失败时为 0。
- `trusted` 控制报告可阅读，但不作为模型成绩或比较记录。未评分和条件缺失的记录也不进入比较。
- 本地报告可编辑，不把导入过程描述成浏览器执行候选程序或不可伪造的认证。
- 旧 localStorage 键 `research-benchmark-prototype-v1` 保持。旧字段及未识别记录保留；损坏存储不覆盖，可导出原始字符串。
- 自动报告保存、信息编辑、删除确认、单条/全部备份、备份合并恢复。重复内容跳过；相同 ID 的不同内容分开保留。
- 模型比较按题库、验证器、种子、平台、工具、环境、镜像、预算规则与尝试规则分组；逐题再核对预算、题包和检查清单。默认尝试 #1；重复且相互冲突的 #1 不自动选优。显示覆盖率与共同子集均分，缺测不填零。

## 已实际执行的检查

运行：

```text
node --check dist/app.js
node --check dist/report-validation.js
node checks.cjs
```

`checks.cjs` 实际通过 **65 项 Node 合同/状态核验**，覆盖报告篡改拒绝、0/null、旧记录保留、真实保存/导入/删除处理器、同条件比较、镜像与预算分组、重复首次尝试处理、旧题包哈希和新题包文件存在。

另外读取评分器实际生成的 `P01-reference-control.json` 与 `P01-unscored.json`：前者在网页验证函数中得到 100 分并标记控制用途、不可比较；后者保持 null 未评分、不可比较。这两条只用于校验功能，不是模型成绩。

## 核验边界

上述 65 项使用 DOM 替身，不能代替真实浏览器的布局、点击、下载、文件选择器、剪贴板和本地存储行为。真实浏览器 QA 由主代理在统一预览中执行并另行报告。

Drive 下载链接由主代理上传文件后回填 `dist/release-data.js`。未登记链接时按钮显示“暂未就绪”，不会伪造可用地址。

新增当前题面的路径为 `dist/packets-v2/`。评分器源内容变化后，必须重新生成 grading manifest、题面与真实样例，再核验导入；浏览器拒绝旧指纹。

## 浏览器实测问题修复

主代理在 HTTP 预览实际发现 `crypto.randomUUID` 缺失造成保存失败。现已统一使用 `newRecordId()`：可用时采用 `randomUUID`，否则采用 `getRandomValues`，再回退到时间戳、递增序号和随机值。本地记录 ID 不用作安全凭证。保存、备份冲突及原始损坏内容恢复均已覆盖；新增无 `randomUUID` 的保存/备份回归及无 crypto 的 ID 区分核验。实际浏览器复验由主代理继续完成。
