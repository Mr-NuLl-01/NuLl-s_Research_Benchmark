## 使用路径

1. **题库 → 题目。** 查看难度、任务合同、完整题面与版本。
2. **Google Drive 获取材料。** 下载候选题包和本地验证器。候选模型只接收题包；评分器由评测者保管。
3. **本地验证。** 将完整候选实现放入评分器已有的 `submissions/P01/solution.py` 等对应题目目录，按包内 README 准备环境后运行：

   ```text
   python -m nrb_v2 grade --task P01 --source submissions/P01/solution.py --execution docker --out results/P01.json
   ```

4. **导入报告。** 在网页选择对应题目，上传生成的 JSON 或粘贴完整报告。网页核验并重算分数，显示逐项结果和失败说明。
5. **保存与比较。** 填写精确模型、版本、推理强度、测试条件及尝试编号；保存到本浏览器，并在相同条件下比较。

各详情页有明确返回入口，题库筛选在返回时保留。上传 `.py` 会说明本地验证步骤，不声称网页已经执行 Python。

## 自动评分与信任范围

本轮协议为 `nrb-auto-report-v2` / `2.0.0-rc.1`。Python 每题全自动 100 分，不提供人工加分输入。

浏览器从当前发布白名单核对题号、版本、种子、题包指纹、验证器内容指纹及测试清单，再使用白名单中的权重重算：

```text
总分 = 100 × 通过检查的权重 / 全部检查权重
```

不能通过删掉失败检查、重复通过检查、篡改权重或只填写一个 `score` 字段得到分数。网页拒绝汇总结果与逐项检查不一致的报告。

- 全部检查通过：`passed`，100 分。
- 检查已执行但存在失败：保留实际部分分或 0 分。
- 有未执行检查：`unscored`，分数为 `null`；不将环境不可用当作零分。
- 整个 worker 失败，即 `execution.status = failed`：本发行要求所有检查失败且分数为 0。正常的部分数值失败使用 `execution.status = executed`、`report.status = failed`。
- `trusted` 作者自检报告单独标记为控制用途，不进入模型成绩或模型比较。

网页不执行候选源码，不调用模型 API。导入的是本地验证报告；JSON 可被人为编辑，内容指纹也不是签名。本轮是私人可复算记录，不提供不可伪造的执行认证。

评分器源内容发生变化后必须重新生成发布清单和真实 QA 报告。旧指纹会被拒绝，不能混用。

## Google Drive 资源

题目和验证器下载使用 `dist/release-data.js` 中已登记的 Google Drive HTTPS 地址，不依赖原先的文件下载代理，不在浏览器中跨域抓取私有 Drive 文件。资源未登记时显示“暂未就绪”，不生成假链接。

下载尊重原文件的 Google 账号权限；本轮不将站点或素材改为公开分享。旧视频 A/B 媒体链接与历史题面继续保留。用户自己的评分记录和备份通过浏览器即时导出 JSON，不需要先上传到 Drive。

## 记录、备份与恢复

保留原 localStorage 键：`research-benchmark-prototype-v1`。载入时不覆盖、不自动迁移旧记录；未识别字段保留。无法解析的原始字符串不会被覆盖，并可随备份导出。

当前支持：

- 保存自动评分报告与模型/环境元信息；
- 查看逐项结果、来源身份和完整运行条件；
- 编辑测试信息，分数继续由报告确定；
- 单条导出、原始报告导出、全部记录备份；
- 导入备份并合并，相同内容跳过，相同 ID 的不同内容分开保留；
- 经确认删除单条本地记录。

记录只存在当前浏览器，不自动云同步。存储写入失败会明确提示并保留内存中的数据，用户可立即导出。清理浏览器数据前应备份。

## 模型比较

比较页先匹配题库版本、验证器、测试种子、作答平台、工具、运行环境、实际 Docker 镜像标识、预算规则和尝试规则；逐题再对齐题包、测试清单与实际预算。

默认比较尝试 #1。重复且相互冲突的 #1 会提示核对，不自动选最高分或最近一次。参考解和故意错误控制不参与模型结果。条件缺失、未评分、无效报告与旧版手工分不混入新版比较。

显示各模型的 8 题覆盖数及双方共同子集均分。缺测留空；仅部分题目配对时明确标注，不给出完整 8 题或 20 题结论。本轮不会生成 20 题总分。
