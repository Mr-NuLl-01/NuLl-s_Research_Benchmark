# NRB V2 · 网页源码与使用合同

本目录是 NuLl 科研 AI Benchmark 的静态 HTML/CSS/JavaScript 网页源码。当前源码对应 **2.0.0完整20题**：8道Python、3道Fortran、1道Lean、6道主观科研题和2道聊天题。全部20题已接入题库，其中 **13道自动评分、7道量表评阅**。

这里记录实现与已执行的合同检查。最终下载资源、部署产物与真实浏览器验收仍需分别取得发布证据，不能由源码检查通过推定完成。

- 既有站点：<https://research-benchmark-notebook.null-00-llun.chatgpt.site>。
- Benchmark公开源码：<https://github.com/Mr-NuLl-01/NuLl-s_Research_Benchmark>。
- 静态入口：`dist/index.html`；当前题面：`dist/packets-v2/`。

原21道V1.1题目保留在历史入口与`dist/packets/`。第一轮V2记录按冻结的旧版本合同保留，不重标为当前20题成绩。题目难度属于设计先验，尚未用真实模型成绩标定。

## 三条提交路径

从题库选择任务，查看题面并获取所选单题材料。每次使用新会话，只向候选提供该题允许的输入；评测者保管验证器与评阅材料。

|任务|交付与评分|网页入口|
|---|---|---|
|P01–P08、F01–F03、L01，共12道程序题|Python交`solution.py`，Fortran交`solution.f90`，Lean交`proofs.json`；本地验证器实际执行后生成JSON报告|导入评分报告|
|H02，共1道定量推理题|交题面要求的原始`answer.json`；网页直接重新计算数值与证书，也接受包含原答案的离线报告|提交答案|
|R01–R06与H01，共7道人工题|观察实际图文、代码、视频或HTML成果，按维度填写等级、必要条件及证据，再由程序计算分数|开始评阅|

### 程序题

把完整提交放入验证器的对应`submissions/<题号>/`目录。首次运行`Build-Environment`准备宿主依赖和两个Docker镜像，再运行`Grade-Results`，或使用单题命令：

```bash
python -m nrb_v2 grade --task F01 --source submissions/F01/solution.f90 --out results/F01-run01.json
```

Python、Fortran和Lean均无人工加分步骤。网页上传或粘贴单题JSON报告后，核对版本、种子、题面、验证器和测试清单，重新计算得分，再保存模型与运行条件。上传程序源码时会提示先运行本地验证器；网页不执行这些候选程序。

### H02

在H02提交区粘贴或上传原始JSON。网页重新验证产额、吸收时间、条件寿命与方差、全局最优证书和合法反例，不采用候选自填的总分。也可在本地验证器检查`answer.json`；导入离线H02报告时，网页仍核对其中的原始答案。H02校验不需要执行候选代码。

### 主观题与H01

先观察实际交付物，再按0–4级和公开锚点填写维度。已评等级、必要条件判断与观察记录均需具体证据，并填写评阅人和提交编号。网页可辅助预览HTML、图片、SVG、视频和文字；预览与算分程序不代替实际读图、阅读、听音、连续视频观察或交互验收。

每维得分为`权重 × 等级 / 4`，各维权重合计100。明确失败且有证据的必要条件会触发公开上限；多个上限取最小值。任一必需维度、观察、身份或责任尚未评阅时，总分保持`null`，已评部分不会冒充完整成绩。确认未提交文件可记为`missing`；评阅环境打不开或尚未查看时保持`unassessed`。

人类评阅标为`human`；模型辅助评阅保留`llm_provisional`身份。完整的LLM暂评可以计算分数，但不进入当前人类评阅的可比队列。详细合同见[主观评阅协议](../docs/v2.0/subjective-protocol.md)。

## R06模式

R06只有一个题号，运行前必须选择A或B，没有默认模式。A根据文字独立制作，材料不含参考成片；B额外提供参考成片，用于观察和重建。两个模式都不向候选提供作者演示代码。

题目页按选定模式获取材料，评阅页绑定同一模式及其输入指纹。不得完成两种模式后择优作为同一次成绩。A违规接触参考、B复制参考帧充当重建等协议不符，按公开规则限制分数，并标记`protocol_eligible = false`，不进入有效比较。尚未判断模式完整性时保持未评。

## 分数、身份与可信范围

当前自动报告协议为`nrb-auto-report-v2`、版本`2.0.0`；H02网页答案封装为`nrb-answer-v2`；人工记录为`nrb-v2-manual-review`。

自动题统一按`100 × 通过检查权重 / 全部检查权重`计算。检查权重仍采用20/30/20的相对配置，合计70后换算到百分制，不存在剩余人工30分。全部通过为`passed`；已执行后失败保留真实部分分或0分；执行环境不可用为`unscored/null`。整个worker失败只接受全部检查失败和0分，不能保留伪造的通过项。

网页拒绝缺失、重复、未知检查，篡改权重，错误类型和不一致汇总，也拒绝错误版本、题面、测试清单或验证器指纹。人工记录额外绑定量表、实际输入材料和R06模式；旧记录缺少这些绑定时不会自动升级为当前有效评阅。

`trusted`参考与错误控制报告只用于实现自检，不作为模型成绩。网页不调用模型API。普通JSON及SHA-256可用于核对内容身份和分数一致性，但不是不可伪造签名，也不能独立认证候选程序确实按所述环境执行。评分实现变化后，必须同步重建清单与检查证据。

## 记录与同条件比较

记录保存在当前浏览器，沿用`research-benchmark-prototype-v1`存储键，不自动云同步。旧字段及未识别记录保留；无法解析的原始内容不直接覆盖，可随备份导出。支持保存、编辑运行信息、查看证据、单条及全部备份、合并恢复和确认删除。相同内容跳过；相同ID的不同内容分别保留。存储失败会提示用户导出内存中的数据。

比较先对齐题库版本、验证器、种子、平台、工具、环境、预算规则和尝试规则；逐题再对齐题面、检查或量表、输入身份、实际预算、评分方式、Docker镜像、视频模式及具体评阅人。只使用条件完整、已评分且具备比较资格的记录。人工题还要求完整人类评阅、模式协议有效；LLM暂评、未评完、控制数据和模式违规结果不混入。

默认比较尝试#1。相互冲突的重复#1会要求核对，不自动选最高分或最近一次。每个模型显示覆盖数；共同子集均分只覆盖已对齐题目，缺测和环境不可用不补零。当前版本只有全部20题都取得同条件可比结果时才显示完整20题等权均分。R06始终只计一题。历史版本按其原题组独立展示。

题目详情、评分和记录页提供返回路径；题库筛选与滚动位置在返回时保留。新增表单输入会清除过期评分预览，避免把修改前的结果保存为修改后的记录。人工评阅文件开始导入时先清除已接受结果；非法或超大文件不会保留旧分数和保存入口。导入绑定发起时的题号、模式及表单状态，读取期间编辑、重新计算、换题、切模式或离开后，迟到的成功与错误均不会覆盖当前草稿。

## 下载与发布

题包和验证器入口使用`dist/release-data.js`中登记的Google Drive HTTPS地址，遵循原文件账号权限。未登记资源保持不可用，不伪造链接；浏览器不跨域抓取私有Drive文件。自己的评分记录备份由浏览器直接导出，不先上传到Drive。

20题主包供评测者分发，每次只提供其中一个任务目录；R06只提供A/B中选定的一个目录。最终Drive文件可下载性、文件哈希与站点发布一致性属于独立发布验收，本文件不将它们标为已经完成。

## 代码与已执行核验

在仓库根目录运行：

```bash
node --check web/dist/app.js
node --check web/dist/report-validation.js
node --check web/dist/h02-grader.js
node --check web/dist/manual-grader.js
node web/checks.cjs
```

在独立站点源码目录中运行 `node checks.cjs`；脚本及测试夹具随源码保留，不包含在公开静态资源目录中。

当前`checks.cjs`实际通过 **83项Node合同/状态检查**，包含人工文件导入的9个异步边界场景。另有Python测试通过Node执行H02与人工评分模块，核对两端的数值、类型、指纹、空分、上限与比较资格。2026-10-23已在预览站实际验证R06坏文件清除旧结果、评阅草稿导出/导入及A/B表单切换；使用合成控制，没有产生模型成绩。完整范围及尚待验证项见[前端QA](FRONTEND-QA.md)。

Node中的DOM替身不能替代真实浏览器的布局、文件选择、下载、剪贴板与存储验收。`benchmark-preview.html`是历史设计样稿，当前入口为`dist/index.html`。
