# NRB 2.0：R01–R06 / H01 实际评阅协议

## 1. 范围

本协议覆盖六道主观科研题和一道聊天端 HTML 题；R06 的 A/B 是同题的预先声明模式，不是两道可择优计分的题。程序题和 H02 不使用本量表。每题 100 分，只有实际提交和已完成评阅才产生分数。本文件与评阅量表供评阅端使用，不进入候选包。

题目沿用第一轮已确定方向：R01 参考学习/可编辑 SVG；R02 特殊数据绘图；R03 保守润色；R04 图文数据写作；R05 三文综合与两项有界复现；R06 视频制作/重建；H01 单 HTML 工作台。设计难度是先验，不代表已测模型区分度。

本轮提供可执行的**评分记录校验与算分程序**，不声称自动判断视觉质量、学术文字或视频表现。`score_review()` 将人类或明确标记的暂定 LLM 观察转换成一致分数；它不能凭候选自述认证作品。

## 2. 材料与候选隔离

候选只收到 `candidate_inputs(task_id, mode)` 的明确清单。单题入口统一为 `<tid>.md`（例如 `R01.md`、`H01.md`），由 `candidate(task_id, 17)` 加上本轮版本与种子；包内不再另放一份原始 `TASK.md`。相对资产路径在包中保持可用。作者参考解、评分器、完整评阅量表、已填评阅记录、历史候选成绩不进入候选目录。

|题号|实际提供的输入|必须观察/运行的提交|
|---|---|---|
|R01|3 幅真实参考图及原图注/许可；配对和独立瞬态 CSV|SVG/PNG 最终尺寸、可编辑源、图注、设计说明和数据编码|
|R02|配对、剂量与扩展不确定度、signed/censored 三个 CSV|主图/替代尺度、Python 再生成、计算、逐轴解释|
|R03|指定原稿和独立的 F01–F11 作者批准事实|润色正文、台账、编辑备忘；不得借其他题数据重算批准值|
|R04|实际 F1 SVG/PNG、两张底层 CSV、记录与故意可疑的 rough notes|输入图读图、稿件、图注、脚本输出、逐主张证据|
|R05|归档三篇完整指定主文/图注/图、给定 P1 S1 及原 DOCX、两组合成复现数据|有界综述、比较/证据、两项代码与实际数值/图形|
|R06 A|源视频、统一音轨、字体及许可、文案、六段说明；无参考成片|全片、六段时间证据、抠像移动边缘/遮挡、音轨、源项目和实际媒体参数|
|R06 B|A 的共同材料，加参考成片|以上，加完整参考观察及结构重建；复制参考帧不等于重建|
|H01|三张原始数据 CSV；单 HTML 功能合同|离线实际打开、正常/空态/返回/重置、CSV 下载、合法/非法导入、键盘/窄屏|

R01/R05 的引用来自已归档源材料；无需要求候选外部搜索。阅读室保留已供应主文及图，不把未供应 SI、外部代码或参考文献全文算为已读。R05 取消重复的三份长来源卡、术语长表及独立证据图，保留一份综合文稿、集中比较/证据表和两项局部复现，避免用文书重复代替难度。

`nrb_v2/subjective_rubrics.json` 是评阅端机器源；`tasks/v2.0/assets/` 中只有按清单选中的文件进入候选包。R06 A 严禁包含 reference.mp4、参考截图、demo_project 或 evaluator 目录；B 也只额外提供成片，不给作者实现代码。共同任务说明可以解释 A/B 合同，但不能通过说明夹入参考帧。

## 3. 运行与评阅条件

先固定模型/版本、工具/skills、推理强度、预算、尝试规则与题库版本。每题新会话，候选不能接触其他题的答案或作者评阅材料。保留首次输出、重试和人工介入记录。未暴露的 token/费用等为 null，不猜测。

盲评时隐藏模型/供应商/价格与先前分数，保留匿名 submission_id。阅读和观察实际文件后填写量表；每个已评维度和通过/失败责任都需要具体证据。证据建议写成 `文件名/面板/时间戳/操作 → 实际看到什么 → 为什么对应锚点`，可附真实 SHA-256，不能仅写“不错”“通过”。

允许人类评阅 `human` 或暂定模型评阅 `llm_provisional`。后者必须实际接收并能观察所需模态，不得伪装成人类认证。比较队列必须区分这两类 authority。若有两位独立评阅，保留两份记录及分歧，裁决不覆盖原记录；单评阅结果应如实披露。

无浏览器、无媒体解码器、无法收听等**评阅环境不足**意味着该观察 unassessed。候选确实未提交文件则可根据清单/文件系统观察记 missing，属于真实交付缺失。两者不能混淆。

## 4. 0–4 级与上限

每维权重固定，公布 0/2/4 锚点；1 和 3 表示在相邻锚点之间有具体证据的表现，不用于表达“我没有看”。维度得分为 `weight × level / 4`，权重合计 100。未评等级为 null。

两端采用 JSON 整数值语义：接受有限、值为 0–4 整数的数值（`4` 与 `4.0` 相同），输出等级统一为整数；拒绝布尔、字符串、非整数、NaN/Infinity。

核心责任用 pass / fail / unassessed。确认 fail 且有证据时，应用题面已公开的总分上限；多个上限取最小值。不是每个一般缺点都会触发上限：例如图注中一个普通拼写问题应进入对应维度，不可任意升级为科学数据捏造。

最终分数仅在全部维度、核心责任、必需观察、评阅者和提交身份均已填写后计算：

`raw_score = Σ(weight × level / 4)`

`score = min(raw_score, 所有已证据触发的上限)`

任一必须项 unassessed → `score = null`。partial_earned 只是已评维度获得的分值，不缩小分母，不显示为完整百分制成绩。requirements_passed 单独报告；高分不覆盖失败责任。不存在暗中的“80 分就全部完成”门槛。

|题号|已公开上限（仅明确失败时）|
|---|---|
|R01|科学数据失真 40；无可用可编辑 SVG 35；未作三图参考学习 70|
|R02|符号/配对/删失语义失真 40；无实际图 30；无可运行源码 60|
|R03|关键事实被改写 35；无说明保留/强化无证据科学宣称 45；无有效台账 70|
|R04|捏造或无证据机理/耐久断言 40；不解释两个真实面板 60；无可追溯计算 65|
|R05|编造或夸大证据 40；任一必需局部方法无实际成果 60；缺要求的三文/P1 S1 使用 65|
|R06|无可播放成片 0；源人物/时序实质不符 40；无可编辑工程 70；音轨或必要署名缺失各 80；模式违规 0|
|H01|无实际离线 HTML 35；交互仅装饰 40；科学语义失真 45；导出错配或非法导入破坏状态 60|

R06 模式违规属于实验条件破坏，除上限 0 外，应标注不能作为该模式合格运行；不能简单把它当低质量作品混进有效比较。算分结果 `protocol_eligible` 为 false；未判断模式完整性则为 null，pass 为 true。完整可比汇总要求此字段为 true。环境不可用或未完成观察继续保留 null，不用 0 代替。

## 5. 实际核验步骤

### 图形与写作 R01–R04

先读输入和定义，再观察实际成果；不要让语言流畅掩盖数字错误。R01 核查所有器件身份、独立实验和参考对应；R02 对照原始负值/零/删失及 U(k=2)，实际运行再生成并比较；R03 使用本题批准记录而不是其他题数据；R04 核查 F1b 是样本 SD、D08 的配对变化为负以及两个实验不能合并成因果链。核验仅针对任务提供的证据，不新增未给出的统计门槛。

### 文献 R05

阅读足以支持每条评分的实际主文、图和相关 S1；不能以文章标题、摘要或文件下载成功代替精读。核查 P1 抽样阶段/分母；区别 P2 建议和实证；核对 P3 实际表达式与坐标，不从术语直接猜测实现。运行两项方法，重算摘要并观察输出；代码文件存在不是复现成功。表达式存在原文歧义时，接受有明确来源定位、忠实实施和有界说明的合理处理，不按未公开答案偏好惩罚。

### 视频 R06

- 先查 run-record mode 与输入清单。A 评阅不能增加隐含参考相似度要求。B 先看完整给定参考。
- 完整看源与候选成片，另外逐段检查 0–1.5、1.5–4、4–5.5、5.5–7、7–8.5、8.5–10 s；每段至少一条带时间的观察。移动边缘、轨道深度和虹膜转场要看连续片段，不能靠 contact sheet 代替。
- 用实际 ffprobe/等价工具获取尺寸、fps、帧数、时长、编码；检查解码错误。音频需真实收听并检查统一音轨，AAC 压缩导致 PCM/容器字节不同本身不是替换音轨的证据。
- 原始源时序应一对一；必要时对照相应源帧和工程。直接复制 B 参考成片不视为独立实现。参考的技术 QA 只描述作者示例，不构成候选模型得分。

### 工作台 H01

机器源 `reviewer_checks` 给出固定操作序列：12 器件初始 → B2 + ` d0 ` → D08 详情和返回 → B2 + D01 空态 → B2 CSV 导出 → 状态导出/有效恢复 → 坏 JSON/未知 schema/未知批次/非法模式逐个导入 → 尺度/符号/删失 → 1280/390 px 与键盘。

看实际下载文件，不只看按钮文字；非法导入后与导入前状态比较，避免部分更新。空态导出接受“禁用且说明”或“仅表头 CSV”两种明示选择。所有验收均来自题面公开合同，没有隐藏 UI 文案或某个框架要求。

## 6. 程序接口与记录

```python
from nrb_v2.subjective import (
    tasks, get_task, candidate_inputs, rubric_spec, rubric_hash,
    blank_review, score_review,
)

# R06 must supply a mode before candidate materials or review are created.
inputs = candidate_inputs('R06', mode='A')
review = blank_review('R06', mode='A', reviewer_id='reviewer-01',
                      reviewer_kind='human', submission_id='anonymous-001')
# Fill actual ratings, requirements and observations; null means not assessed.
result = score_review(review)
```

input mappings 为 `{source: repo-relative-path, path: packet-relative-path}`；清单中的题面源文件经 `candidate()` 包装后交付，其余附件按原字节复制。`rubric_spec()` 是完整评阅合同，`rubric_hash()` 为规范 JSON 的 SHA-256。报告同时绑定当前 `benchmark_version`、题号、模式、`rubric_hash`、`packet_hash` 和 `input_manifest_hash`。`packet_hash` 对应实际交付的带版本题面；`input_manifest(task_id, 17, mode)` 对每个交付文件记录路径、字节数和 SHA-256，再对完整清单计算 `input_manifest_hash`，因此 R06 A/B 分别绑定各自的输入材料。旧记录缺少任一必需绑定、或者版本/指纹不匹配时明确拒绝，不自动迁移成当前成绩。

评分器也拒绝缺失/重复/未知维度或责任、布尔冒充等级、非法分值和无证据判定。上报总分不被采用，统一重算。`comparison_key` 包含上述题目/版本/模式/三个指纹以及 `reviewer_kind` 和 `reviewer_id`；不同模式、不同具体评阅者、人类与 LLM 暂评不混成同一配对条件。网页只有完整、人类评阅且 `protocol_eligible` 为 true 的结果可以进入可比队列。LLM 暂评可以完整算分，但仍显式保留暂评身份。SHA-256 是字节身份，不是可信签名；这是私人评阅记录，不声称服务器认证作者或实际行为。

`observations.status` 为 observed / missing / unassessed。`artifact_sha256` 与 `submission_sha256` 可为 null，若填则必须是实际小写 64 位摘要；缺少摘要不得伪装成已绑定字节。用于正式对比时应从真实提交归档生成摘要。手工评级仍不能因摘要有效就自动获得科学/视觉质量认证。

## 7. 本轮验收范围

本轮开发检验题面/量表/材料可用性、候选隔离、R06 模式清单和算分逻辑，不能替代实际模型作答。单元控制包括：正确算分、上限、未知与确认缺失、缺证据、重复维度、布尔/非整数分值、错版本/题面/输入/量表指纹、模式及具体评阅者/暂定 LLM 比较身份。`tests_v2/test_web_subjective.py` 用 Node 实际执行网页评分器，与 Python 的八份模式量表逐字段比较，并验证不可比结果不会进入网页对比队列。真实视觉/交互质量必须在未来候选成果产生后按本协议观察。
