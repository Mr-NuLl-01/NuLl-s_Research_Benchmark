# NRB 2.0 第一轮使用指南

适用版本：`2.0.0-rc.1`。当前可自动评分：P01–P08。每题满分 100，全部由程序检查得到。

## 1. 给被测模型什么文件

从网页或 Google Drive 下载所选单题，例如 `P04.md`。在一个新会话中只提供这份候选题面。题内已包含任务定义、输入输出、示例及需要修复的起始代码（如适用）。不要把验证器 ZIP、维护者文档或整个仓库一并交给模型。

要求模型交付完整的 UTF-8 `solution.py`，其中定义 `solve(problem)`。可以同时给科学说明和自测，但本轮不对这些附件设置人工分。没有工具的聊天模型也可以返回完整源码，随后由评测者保存为 `solution.py`；必须如实记录其未在作答端执行。

题库设计难度不是已经测得的成功率。若要比较模型，预先固定模型版本、推理强度、工具、skills、子代理权限、总预算和尝试规则。不要测试后选最好一次而不保留失败记录。

## 2. 下载验证器并评分

下载 `NRB-v2.0.0-rc.1-python-grader.zip`，完整解压。验证器中有 P01–P08 的独立提交文件夹。

1. 把该题的代码放入相应目录，例如 `submissions/P04/solution.py`。
2. 首次使用时，安装并启动 Docker Desktop，然后运行 `Build-Environment.cmd`（Windows）或 `Build-Environment.command`（macOS）；Linux 可以运行 `sh Build-Environment.sh`。
3. 运行 `Grade-Results.cmd`（Windows）或 `Grade-Results.command`（macOS）；Linux 运行 `sh Grade-Results.sh`。
4. 脚本会生成一个新的 `results/<运行时间>/` 目录，避免覆盖旧尝试。打开其中 `index.html` 查看得分、检查明细和错误原因。
5. 将该目录内的单题 JSON（如 `P04.json`）导入网页，即可保存为模型测试记录。

验证器宿主需要 Python 3.11 或以上；候选容器使用题面固定的 Python 3.12、NumPy 2.3.5、SciPy 1.17.0。第一次构建需要下载环境；构建后候选运行断网。Docker 没有安装、没有启动或镜像没有构建时，结果显示环境不可用和空分，并给出下一步说明，不给模型记 0 分。

如果 macOS 没有把 `.command` 识别为可运行文件，在终端进入已经解压的验证器目录，执行：

```bash
sh Build-Environment.sh
sh Grade-Results.sh
```

不要把验证器本身交给被测模型。下载包包含评分实现和预期计算逻辑，适合评测者使用。

### 命令行单题

在验证器目录运行：

```bash
python -m nrb_v2 grade \
  --task P04 \
  --source submissions/P04/solution.py \
  --execution docker \
  --seed 17 \
  --out results/P04-run01.json
```

Windows 可以写成一行，并按自己的 Python 安装使用 `py -3` 替换 `python`。macOS/Linux 如无 `python` 命令，可用 `python3`。

### 命令行批量

```bash
python -m nrb_v2 batch \
  --input submissions \
  --out-dir results/run01 \
  --execution docker \
  --seed 17
```

未放代码的题显示 `not_submitted`，不进入已评分覆盖。重复测试请换一个输出目录；原结果不覆盖。网页当前接受发行清单中的种子 `0`、`17`、`2026`，默认使用 `17`。网页每道题默认展示种子17候选包；更换候选种子时用 CLI 生成对应题面。

`trusted` 模式只供维护者执行已审读的参考和错误控制，不是普通候选提交的默认方式。普通 `grade`/`batch` 使用 Docker。网页不会把只导入 JSON 表述为重新执行了源程序。

## 3. 如何理解报告

|状态/字段|含义|
|---|---|
|`passed` / 全部检查通过|所有规定检查均实际执行并通过|
|`failed` / 检查失败|实际执行后存在不通过项；保留部分分或0分|
|`unscored` / 环境不可用|没有完整执行证据，分数为 `null`|
|`not_submitted`|批量目录中尚未提交该题|
|`submission_invalid`|提交编码、大小或路径不合法；给出原因并继续其他题|
|`score`|按当前版本检查权重计算的百分制分数|
|`critical_passed`|关键检查的状态；与总分一并查看|
|`checks`|每项检查 ID、分组、权重、通过/失败/未执行与原因|
|`submission_hash`|参与本次验证的提交内容身份|
|`packet_hash`|所用题面与协议的身份|
|`test_manifest_hash`|当前题号与种子的完整检查集身份|
|`evaluator_fingerprint`|当前评分器内容身份|

可下载报告是可编辑文件。指纹用于发现版本混用和内容变化，不等同于不可伪造的签名。网页将其标为本地报告导入。正式公开榜单的执行认证不属于本轮。

单题分数来自全部自动权重。现有检查权重合计70，按 `100 × 通过权重 / 70` 变成100分；这不是把旧人工分自动补满。没有评审人、没有人工质量分，也没有因为缺少 `report.md` 而等待人工。

总览同时显示完成数量与覆盖率。仅测3题时，可查看这3题的子集均分；不能当作“八题总分”或“二十题完整成绩”。环境缺失保持空值，不能算0也不能冒充完成。

## 4. 网页操作

### 从题目到结果

打开分级题库，选择一题。详情中先获取候选文件，再获取验证器。获得本地报告后点击“导入自动评分报告”，选择对应JSON，检查识别的题号、版本、种子、各项结果和总分，然后填写模型及运行条件，保存记录。

如果选中的是 `solution.py` 或未评分提交文件，网页会提示使用本地验证器生成报告。前端没有 Python 执行服务，因此不会假装已经运行。

### 错误与重试

非法 JSON、题号不符、未知版本、检查项缺失或重复、权重改变、分数不一致都会给出可理解的提示。保留原文件，使用同一发行版验证器重新生成；不要手工补造通过项。

关闭详情或点击返回后，应回到此前题库筛选。记录保存后可以继续查看逐项检查、返回结果列表或开始下一次测试。

### 历史记录

原 V1 题面、原来的模型记录和手工草稿保留为历史。旧题号 C01–C10 与新 P/F 题号只建立来源关系，不自动重标成新版本成绩。历史草稿不参与当前自动评分比较。

### 备份和恢复

记录存在当前浏览器，不自动作云同步。通过“导出记录”保存完整 JSON，之后可以导入恢复。清理浏览器数据或换电脑前先备份。页面保存失败会提示；不要把尚在内存中的内容当作已持久保存。

网页提供的题目资源从 Drive 下载；本地记录备份则由浏览器直接导出。导出记录不触发 Drive 上传。

## 5. 单题提交提示词

```text
请完成附件中的 NRB Python 任务。以附件题面为准，交付完整的 solution.py，
其中提供 solve(problem)，严格遵守输入、输出、异常和算法合同。

只使用题面允许的材料与工具，不访问 benchmark 仓库、验证器、参考解或其他测试会话。
不要硬编码示例答案。若允许执行工具，请实际运行你自己的必要验证并修复。
若无法执行，请直接交付完整源代码并如实说明未执行，不要声称测试已通过。
科学说明和自测代码可另附，但不要把它们写进函数返回值。
```

## 6. 第二轮接续

第二轮应从仓库当前第一轮提交和私有站点继续，完成 F01–F03、L01、R01–R06、H01–H02；不要重写已完成的八道 Python 题或把历史草稿升级为真实成绩。第二轮开始前先读取 `docs/v2.0/round2-handoff.md`，核查当前版本与实际交付状态。
