# NRB 2.0 使用指南

适用版本：`2.0.0`，完整20题。题目结构为8道Python、3道Fortran、1道Lean、6道主观科研、2道聊天端。自动评分13题；人工证据量表7题。

## 选择题目与材料

网页题库中选择一道题，下载 Google Drive 单题候选 ZIP。解压后将 `<题号>.md` 和同包允许的附件交给被测模型。P01–P08 的完整起始代码和例题已在题面内；L01 提供固定定义、工具链标记和空证明模板；主观题包含实际数据、图、阅读室或视频源素材。

R06 必须在作答前选 A（独立修改）或 B（参考视觉重建）。A 包没有参考成片或截图，B 包才包含参考成片。它们计一道题，不能把两个模式各记一次，也不能测试后择优。完整合集同时含两种模式，应由评测者保管，只交付预定单题单模式。

每题使用新会话，预先固定模型快照、推理强度、允许工具/Skills/子代理、作答预算与尝试规则。题面的时间为参考预算，难度为设计先验。记录实际测试条件，不把未执行的自述写成测试证据。验证器、维护者源码和作者控制只在评测端保管。

## 三种提交方式

|题目|模型交付|如何评分|
|---|---|---|
|P01–P08|`solution.py`，公开 `solve(problem)`|本地容器实际执行，网页导入报告|
|F01–F03|`solution.f90`，按题面文本输入输出|实际编译和运行，网页导入报告|
|L01|`proofs.json`，六个固定目标的证明项|固定 Lean 4.19.0 驱动核验，网页导入报告|
|H02|原始 `answer.json`|网页直接粘贴/上传并验算，也可本地验证|
|R01–R06、H01|各题要求的实际文件|打开交付物、实际观察，逐项填写证据量表|

程序题不因缺少 `report.md` 或人工说明而等待评分。各题明确规定的算法、错误处理、输出字段和数值精度仍须遵守。

## 下载验证器

下载 `NRB-v2.0.0-evaluator.zip` 并完整解压。安装 Python 3.11或以上，安装并启动 Docker；第一次环境建立需要网络，候选运行时断网。

1. 运行 `Build-Environment.cmd`（Windows），或 `Build-Environment.command`（macOS），或 `sh Build-Environment.sh`（Linux）。它创建包内 `.nrb-env` 并安装评测端 NumPy 2.3.5，再构建普通科学计算容器与 Lean 容器。
2. 把模型文件放入 `submissions/<题号>/`。例如 `submissions/F02/solution.f90`、`submissions/L01/proofs.json`。占位说明文件不是提交。
3. 运行 `Grade-Results.cmd` / `Grade-Results.command` / `sh Grade-Results.sh`。
4. 打开新建的 `results/<时间>/index.html`，查看13道自动题的提交覆盖、评分和逐项错误。
5. 在网页对应题目选择“导入评分报告”，上传该目录的单题 JSON，再保存模型与测试信息。

如果系统不识别 `.command`，在解压目录运行上述 `.sh`。Windows 可在终端用 `py -3`；macOS/Linux 可用 `python3`。本次未在原生 Windows/macOS 上实测双击启动行为。

环境不可用（没有 Docker、镜像未构建、Lean/编译器不能启动）保留 `unscored/null` 并给出原因。候选语法错误、错误输出、实际超时计为失败。首次环境建立失败时先解决明确错误再运行，不手填分数。

### 命令行单题与批量

以下命令在评测器根目录运行；下载包可用 `.nrb-env/bin/python`（Windows 为 `.nrb-env\Scripts\python.exe`）替代 `python`。

```bash
python -m nrb_v2 grade --task P04 --source submissions/P04/solution.py --seed 17 --out results/P04-run01.json
python -m nrb_v2 grade --task F02 --source submissions/F02/solution.f90 --seed 17 --out results/F02-run01.json
python -m nrb_v2 grade --task L01 --source submissions/L01/proofs.json --seed 17 --out results/L01-run01.json
python -m nrb_v2 grade --task H02 --source submissions/H02/answer.json --out results/H02-run01.json
python -m nrb_v2 batch --input submissions --out-dir results/run01 --seed 17
```

缺少某题文件显示 `not_submitted`，批量继续。非法编码、路径或超限文件单独报告，不吞掉其他题结果。输出目录不能覆盖旧运行；重试使用新目录。完整13道自动题均分和完整20题均分是不同范围，不能互换。

网页自动报告登记种子0、17、2026，默认17；改变候选种子时应使用对应导出题面。H02的固定数学题和主观量表使用默认17。源仓库运行 `pip install -e .` 可安装评测端依赖；只复制一部分模块会缺少题面或附件身份材料。

### H02 直接评分

打开 H02 → 提交答案，将模型给出的严格 JSON 粘贴或上传。网页独立计算吸收概率、无条件/条件时间、条件方差、全局最优证书及合法反例。多个正确反例均可接受。网页不相信答案中的自述总分，也不执行任意提交代码。

H02 也能通过本地CLI评分；本地报告包含原始 `answer_payload`，网页导入后会再次验算，不能仅修改检查项把错误答案变成满分。

### 主观题评阅

打开实际交付物。H01需实际操作筛选、返回、空态、导出和窄屏布局；R06需完整播放、查看六段时序并实际听音频。网页提供可选本地预览，但预览未覆盖的格式或功能仍需在本地检查。

在各维度选择0–4级并填写具体证据，再完成必要条件与观察记录。分数由公开权重计算，必要条件不满足时应用公开上限。`未观察`表示尚未检查或环境无法检查；`已确认缺失`表示实际确认模型没有交付，两者不可互换。必要项目未评完时总分为空，可以保存草稿。R06模式违规的分数保留，但不能进入有效比较。

可导入/导出评阅 JSON。评阅人、提交编号、题面摘要、全部候选附件摘要和量表摘要共同绑定记录。人工评阅和LLM暂评保留不同身份；暂评不进入正式比较。

```bash
python -m nrb_v2 review-template --task R01 --out R01-review.json
python -m nrb_v2 review-template --task R06 --mode A --out R06-A-review.json
python -m nrb_v2 review R01-review.json --out R01-scored-review.json
```

离线命令重算量表，不自动看图、听音频或替评阅人填写证据。详见 [主观协议](subjective-protocol.md)。

## 状态与分数

|状态|含义|
|---|---|
|`passed`|规定自动检查全部实际通过|
|`failed`|存在真实失败，保留部分分或0分|
|`unscored`|不能取得完整执行结果，分数为空|
|`not_submitted`|未提供该题要求的文件|
|`submission_invalid`|文件路径/编码/大小不满足读取合同|
|`reviewed`|必要的主观评级与观察已完成；不代表质量全部达标|
|`review_incomplete`|主观评阅还有未完成项目，分数为空|

自动题相对权重20/30/20，以 `100 × 通过权重 / 70` 归一化。全部检查通过状态与总分同时呈现。主观题按每维 `权重 × 等级 / 4` 相加，再取必要条件上限。

本地JSON可以编辑，哈希是内容/版本一致性检查，不是不可伪造签名。代码报告导入不等于网页重新执行了代码。Lean核验覆盖固定六个命题，采用受限证明语法、内核添加与传递公理检查；不是任意不受限制Lean工程的安全证明，也未声称执行独立外部内核比较器。

## 保存、比较与恢复

评分预览后填写模型名、版本/快照、推理强度和日期，保存记录。在“测试条件与备注”补齐作答平台、工具、环境协议、预算和尝试规则，才能进入同条件比较。环境协议用于整组一致的测试设置，实际容器镜像按各题报告核对。

比较默认使用首次作答，保留失败；同一配置同一题出现不同的首次提交时提示核对，不自动选高分。逐题核对题面、评分合同、实际镜像、预算、R06模式、评阅人；条件不同不配对。完整20题都共同有效时才给完整等权均分，否则显示共同子集与覆盖。仅有3题成绩不能称为完整20题成绩。

原V1题面和手工草稿保留历史身份；第一轮 `2.0.0-rc.1` 报告按原登记协议显示与比较，不自动升级为2.0.0。网页仍使用原存储键。返回题库保留筛选，记录详情可回到列表或题目。

记录只保存在当前浏览器。导出完整备份后可以跨设备导入；导入会合并并保留冲突项，不静默覆盖。浏览器写入失败会显示提示。Google Drive 提供题库与验证器下载，浏览器本地备份不会自动上传Drive。
