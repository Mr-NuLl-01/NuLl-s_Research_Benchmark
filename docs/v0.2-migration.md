## 运行者需要改变什么

1. 固定一个v0.2提交，重新导出题包；旧题包含已变化的数据和字段，不继续复用。
2. NRB03要求 `solve.py` 提供 `solve(problem)->answer_dict`。外部代码用Docker/container执行；只有正确数字不能完成搜索责任。
3. NRB05已有默认起点0兼容；实现还需支持公开的可选 `t_start`。
4. NRB09运行 `review-packet --render`，实际看图后填写核心判断和两项观察确认。缺renderer或看图能力就保持未评。
5. 三项质量分之外，逐一判断全部核心责任。初始都是unassessed，不以固定质量分门槛代替科学判断。
6. Harbor oracle自检要显式 `--include-oracle`；模型包默认无solution。模型API域名用 `--agent-hosts` 单独指定，不自动恢复无限联网。
7. 自动报告、质量ledger和最终报告来自同一评分器、题包、提交与执行条件。改评分源码后重新导出及重评；原分保留历史标签。

## 仍需后续实测的内容

本轮验证明确正负控制及运行协议，没有证明真实前沿模型之间已有稳定分差。NRB01仍是固定证据阅读，NRB07仍是一次性协议计算，NRB08仍需科学审阅。真实多模型校准、双人评分一致性、开放检索和长期研究轨道不借用本轮自检成绩。

镜像探针支持其实际测试的离线隔离边界，不证明某个在线Harbor后端的API白名单或供应商服务端工具已正确关闭。正式候选仍需独立配置与记录，见[测试操作指南](testing-without-answer-access.md)。
