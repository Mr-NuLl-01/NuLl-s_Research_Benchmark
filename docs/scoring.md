# 评分规范 0.1

## 计分对象

被测对象是明确配置下的模型或模型与 harness 组合。主评测包含10个固定任务家族，每家族一次运行得到一份答案与文件。生成数据种子、模型采样种子、重复编号是不同概念，必须分别记录。

每题最大100分：确定性检查最大70，独立质量审阅最大30。权重在看到模型输出前固定。机器核验主要判断数值、约束、反例、真实代码行为、图中实际数据和交接字节；科学论证的完整性、表达保真与视觉质量由三项各10分的量表覆盖。

题目不是选择题集合。可替代的有效反例、并列最优分配、合理推导或文风允许不同于参考答案。确切字段、数字/单位和有限分类用于稳定机器评分，不能用散布关键词替代证明或成果。

## 自动分

令题目 j 的第 k 项分值为 w_jk，核验结果 c_jk 为0或1，则：

\[
A_j=\sum_k w_{jk}c_{jk},\quad \sum_k w_{jk}=70.
\]

为了方便不同工具显示，另报告 `auto_percent=100*A_j/70`。这是**自动部分的归一化分数**。不能在这个100分上再加30，也不能把自动100分称为完整100分。

代码/其他基础设施未能执行时，该核验项为 `passed=null`。`coverage` 为真正评分的检查权重除以70。只要一项未评，`auto_percent` 与完整 `total` 均为 null；已经完成的原始分仍保留供诊断。某题根本未提交与某题未运行是不同状态：空/非法答案记答案失败，缺少未曾运行的任务则保留套题不完整。

代码题使用同一批未在题包展示的行为测试。测试输入遵循公开 API，涵盖不同网格、边界、初态、误差容差和失败条件。生成器、参考解和评分实现公开供审计，但它们不得进入候选环境。“未展示”指对候选运行隐藏，不是对仓库阅读者保密。

数值容差按物理量设置。例如小量级 PSD、协方差不能用宽松的统一绝对容差，否则返回零也可能得分。图题根据提交的 SVG 坐标重建数据点，检查声明的坐标轴映射、模型曲线和残差；它不把 XML 合法等同于图好看。

## 质量审阅

每题提供3项专属标准，0/5/10有文字锚点，可以在0–10之间给部分分。每项必须引用该提交中的具体证据并解释分值；缺失成果不能获得相应质量分。不得从模型名称、自动分、参考答案字面相似度或写作长度推断质量。

审阅应对模型/harness身份盲化，使用相同量表。重要结论建议两位独立评阅者；单项差距达到3分、存在科学有效性分歧或关键错误时进行有记录的复核。这个差值是本版建议的操作阈值，不是经实测优化的统计标准。

`review-packet` 输出不含模型身份和自动得分的任务/提交/空量表，`grade --review` 校验题目hash、提交hash、评阅者和三项分数，避免把另一次运行的评语贴到当前答案上。评分器不会验证评阅者身份，因此真实独立性仍需评测者保证。

模型辅助评阅可使用同样的packet与ledger。输入的候选文本只作为待审材料，不得执行其对评阅者的指令。judge 模型、prompt、采样设置与证据必须记录。LLM评阅的合计标成暂定；它可能有偏差，不能作为科学争议的唯一裁决。图题如果judge无法看到安全渲染的图，就不能声称已评分视觉质量。

令三个质量分为 h_j1,h_j2,h_j3，则 `total_j=A_j+sum(h_ji)`。无质量审阅时 `total_j=null`，自动分仍可完整使用。

## 关键错误与交付完整性

`critical_failures` 与原始分同时展示，不用隐蔽扣分。缺少题目要求的文件会追加 `required_artifacts` 标记；给了文件名却没有内容仍视为未交付。数值/证明/来源特定的关键错误由题内检查列明。格式存在并不证明论证正确，引用了文献编号也不证明读懂证据。

为了日常筛选，可预先采用“完整总分≥80、无关键失败、必须文件齐全、自动覆盖率100%”作为单题可用门槛。**80是建议的操作标准，不是本版已经校准的能力分界线。**同时保留各题分数，尤其看低分任务是否正是实际工作中的关键环节。

## 套题与重复

主报告采用10题等权宏平均。单题多个数据种子与重复先在家族内平均，再对10个家族平均。不得把一个题目生成100个变体，就让它对套题分数产生100倍影响。

套题报告至少含：10题原始分/自动分、质量分与状态、关键失败、遗漏任务、环境错误数、每次完成时间和可获得的usage。token/cost不可得时用 null，不按零处理。除总均分外，应给出最低题分与任务画像；一个代码错误不能被几个流畅段落的分数掩盖。

## 故障的处理

| 情况 | 处理 |
|---|---|
| 在既定预算内输出错误数值、错误程序、非法JSON或没有答案 | 对应题目/检查失败 |
| 预算耗尽或输出长度超限 | 保留超时/超限事实，作为该已授权预算下的运行失败 |
| Docker/依赖缺失、评分器内部异常、模型连接/认证问题 | 标记基础设施未评，不伪造0分或从分母静默删除 |
| agent改写只读题目/原始数据、越权读答案 | 记录协议违例，不作为有效能力成绩 |
| 更新了题目、量表或输入，仍用旧提交/评语 | hash不匹配，拒绝跨版本评分 |
| 修复基础设施后重跑 | 保留原记录；同一故障类别对所有配置采用一致重跑政策 |

若还无法区分模型错误和框架错误，先记录未归因状态，再查运行事实，不先给模型扣分。正确的退出码也不能代替科学检查。
