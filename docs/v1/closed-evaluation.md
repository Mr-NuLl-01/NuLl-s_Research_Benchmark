# 如何测试而不让候选读取答案

## 先明确能保证什么

单独下载一道题，可以消除“为拿题而给候选整个公开仓库”的不必要暴露。真正的闭卷还需要候选运行环境看不到评分器、参考程序、旧答卷和开发对话，并在本轮禁止搜索答案。提示词中的“不要偷看”只是规则，不能代替文件系统与网络隔离。

本仓库公开了参考实现和验收逻辑，便于审计。离线运行无法消除模型训练阶段已经接触公开材料的可能，也无法让公开种子生成器变成保密考试。因此 V1.0 是公开开发与持续回归基准。高可信选型应在相同科学合同下，另由评测者维护未公开的新参数族/数据/负控制，并在评测后审计，不能事后为某个模型改题。

## 推荐的三个环境

**评测者环境**保存本仓库、出题程序、评分器、运行清单和参考实现。它负责准备题包、保存精确 commit/哈希、接收提交、评分。

**候选环境**每题新建，只放一个 `Cxx.md` 或 `Rxx.html/Xxx.html`、已预装工具和空输出目录。不要把评测者的仓库、Home、日志、挂载盘、凭据、Docker socket 或聊天记录暴露给候选。生成结束即冻结输出；评分反馈不返还给同次首次作答。

**验证环境**接收冻结后的候选成果，在隔离运行时执行。期望值始终保留在评分父进程；候选子进程只得到问题输入和自己的代码。Harbor 适配器为 candidate/verifier 分别构建镜像；verifier 断网且评分器为 root 专有，候选代码以 UID 65534 运行。普通 `grade --execution docker` 只挂载候选文件，不挂载仓库。

构建环境安装软件所需的网络与候选作答时的网络是两个阶段。先预装、记录版本，然后关网络。若模型客户端必须调用远程推理 API，只允许必要 API 域名，关闭服务端浏览、联网搜索和远程代码工具；API 白名单不是对上游工具行为的自动保证。

## 无代码界面的最简单用法

1. 评测者打开 [统一题目目录](../../tasks/v1.0/) 并下载一题的真实文件。
2. 新建与开发本基准无关的对话，不复用当前设计/审阅会话。关闭网页搜索、连接到本仓库的工具和不属于本轨道的记忆/文件工具。
3. 上传该单题文件。Markdown 可直接作为文字输入；HTML 要确认客户端能读取正文和内嵌图。不能把 1.5 MB 的 base64 图片文本当作视觉输入。支持文件和浏览器的候选可以离线打开 HTML；纯 API 应由评测者在外部解析并按该 API 的多模态格式传图。
4. 使用固定提示词、时间/工具/输出预算。保留原始答案和工具日志。交付完成后再转入独立评分。
5. 对绘图、写作和媒体任务按人工量表评阅真实成果，不让候选自己宣布满分。

如果平台无法关掉外部记忆或搜索，应标记为开放工具轨道，避免与严格闭卷成绩混比。这是测试条件说明，不意味着该平台必然会读取答案。

## 可复制的候选总提示词

下面仅是统一运行约定，不含参考解或正确判断。单题中更具体的科学合同优先。

```text
你正在参加 NuLl Research Benchmark V1.0 的一次独立测试。
本轮唯一任务材料是我提供的一个题目文件。请完整读取材料及其中图像，按题目完成真实成果。

只能使用本轮声明可用的工具和本文件材料。不要访问 benchmark 仓库、参考程序、评分器、历史答卷、其他对话、搜索引擎或未授权外部文件。

按题目要求交付完整源代码、报告、数据和真实媒体文件。允许执行工具时请实际运行，修复发现的问题；若未运行或缺模态，请如实说明，不要把计划表述为已完成。

Python/Fortran 题按规定接口提交完整 submission.json。其他任务交付题目要求的真实文件，由评测者统一打包。
不要修改题目原文件。预算用尽时提交已有工作并明确剩余缺口。完成后结束本轮，不自行寻找评分反馈。
```

模型、harness、技能和预算由评测者在运行清单另行固定；提示词不要携带个人正在推进的研究背景。公开题已足够自包含。

## Harbor 的具体边界

```bash
# 仅评测者执行
docker build -t nrb-v1:local -f environments/v1/Dockerfile .
python -m nrb_v1 export --format harbor --tasks coding \
  --seed 17 --dest exports/harbor
```

生成的每题中：`environment/` 只含系统构建及候选题；`tests/` 属于独立验证器；默认没有 `solution/` oracle。不要将导出目录整体给候选 shell，也不要把 `verifier.environment_mode` 改成与候选共享环境。

默认 `agent.network_mode=no-network`。确有远程推理需要时，可在出题时给 `--agent-hosts` 精确域名列表；这会形成另一个必须记录的配置。不要为“方便安装依赖”在正式作答期开放整个公网。

仓库的 `harbor_smoke.py` 会为了检验运行链路，在评测者端显式加入 oracle 文件，再运行 oracle agent。它是无模型调用的基础设施自检。**不得拿该自检导出目录作为正式候选环境。**

## 种子、题面匿名化与训练污染

C01–C10 的科学输入随种子变化，制造解也改变内部真值。新种子能避免只背一份可见输入；它不能阻止一个已经记住通用参考实现的模型解决同族问题。R01–R06 当前使用同一份固定文献/数据材料，不应把换种子等同于新的研究题。

正式闭卷可把文件改为中性的本地名称并在评测者清单保存原 ID/hash；修改题面字节会产生新的 packet hash，所有比较对象必须收到完全相同的版本。原生工具默认精确题包身份，不支持悄悄改题又沿用旧分。

当怀疑污染时，记录迹象而不是仅凭高分下结论。有效检查包括新参数范围中的合理变化、未公开的性质测试、解释与代码的一致性、日志中的外部读取，以及用同一科学定义独立生成的留出题。不要把一个无法解释的模型高分直接判作作弊。

## 哪些办法不够

- 删除公开 `answers/` 目录但保留 Git 历史、Python 模块、测试和参考输出。
- 把答案藏在同一候选进程可读的另一个路径或环境变量。
- 只用文件名黑名单，却允许仓库搜索、终端访问、远程浏览或宿主挂载。
- 在开发本基准的这段会话里继续充当未见题的候选。
- 向同一轮候选反复返回隐藏评分明细，然后把最后一次结果报告为首次成功。
- 把框架 mock、参考解或已看答案后的调试运行列入模型排行榜。

闭卷控制的是本轮可访问的信息；公开基准的长期污染风险需要私有留出与版本维护共同处理。
