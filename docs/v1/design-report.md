# NRB V1.0 设计与迁移报告

## 1. 本次重构要解决什么

V1.0 将主评测拆为 **10 道科学编程题 C01–C10、6 道日常科研题 R01–R06**，另设 **3 道可选能力题 X01–X03**。它希望回答两个可以分别复核的问题：候选能否把有边界的科学定义实现成正确程序；候选能否把已有数据、图与文献转成可靠、可编辑、可追踪的科研成果。代码运行结果、科学解释、核心责任和实际模态观察共同组成证据，不能由一项流畅输出替代其他项。

旧版 V0.2 的 NRB01–NRB10 已覆盖证据审计、参数退化、校准设计、数值修复、统计、证明、制图与交接，保留了重要的开发经验。它的十题混合结构仍不足以承载本次需求：科学编程没有形成从数据清理到耦合反演的十题梯度；制图、英语编辑和交接各自只有较窄样例；没有把“同时读几篇实际论文、学习实际图形风格、梳理显式与隐式逻辑、做有限方法复现”组成完整离线任务；视频与音乐也不应被放进文字任务里假装已经评测。

因此本次采用独立轨道，增加有明确接口的计算任务和需要完整人工判断的科研任务。这里的“升级”指对当前工作需求的覆盖与交付协议重构，不表示所有旧能力都被严格包含。旧版的特定证明、鲁棒实验设计和证据冲突任务仍有独立价值；V1 的主集合没有穷尽它们，也没有声称测量真正的长期自主发现、实验室操作或完整器件仿真。任务数量变多本身不证明效度提高，效度还需要后续真实候选试跑和独立复评。

V0.2 的 `nrb`、旧 `questions/` 及历史资料保留，V1 使用 `nrb_v1` 和 `nrb-v1` 入口。旧分数不转换为新分数。数值任务、生成条件、测试分层、人工量表和核心责任都已改变，跨版直接排名没有共同测量基础。历史协议见 [V0.2 说明](../v0.2-README.md)；当前运行身份、执行范围与验证状态应读取本版 [验证记录](validation.md)，不从本设计报告复制一个会过期的提交号或 CI 计数。

## 2. 公开基准提供的设计启发

本次核对了以下官方项目的公开说明，采用其可迁移的评测思想。没有复制这些项目的题目、数据或参考解，也没有运行它们来推断 NRB 分数。这里不引用随时间变化的排行榜数值。

| 官方项目 | 与本设计有关的特点 | NRB 的取舍 |
| --- | --- | --- |
| [SciCode](https://github.com/scicode-bench/SciCode) | 从研究问题分解出需要科学知识、推理与代码实现的子问题 | 用小而完整的科学接口、分层测试和独立关系，检查知识是否落实到计算；不把本套经典合成题声称为 SciCode 等价研究难度。 |
| [CORE-Bench](https://github.com/siegelz/core-bench)，[原论文](https://arxiv.org/abs/2409.11363) | 将计算复现放在代码、运行环境与科学结果的连接中 | 保留真正运行及结果解释，要求 R05 明说部分复现范围；不把两种合成演示说成完整论文复现，也不引入其大型环境安装负担。 |
| [ScienceAgentBench](https://github.com/OSU-NLP-Group/ScienceAgentBench)，[项目页](https://osu-nlp-group.github.io/ScienceAgentBench/) | 面向数据驱动科学任务的独立程序与可检查成果 | 强调实际程序、图、表、来源和交付物，区分模型与工具系统条件；本版仍是目的性选择的有限任务集。 |
| [SWE-bench](https://github.com/SWE-bench/SWE-bench) | 将真实软件问题的修复落实到仓库行为与测试 | C03/C10 采用需要逐类解释的多缺陷修复，检查运行语义而非补丁表面；不宣称合成求解器修复等同大型真实仓库维护。 |

官方说明支持这些项目的任务取向，不能替 NRB 证明难度、可靠性或真实模型区分度。本报告以下关于 NRB 的陈述以仓库中的任务合同、参考执行和验证记录为依据。

## 3. 三类任务怎样组成一套可使用的评测

### 3.1 交付物必须具体而自足

C 题导出为独立 Markdown，含定义、接口、可见输入、资源条件和交付要求。R/X 九题各为一个自包含 HTML，含所需数据、实际图像或指定论文文本，不需要额外抓取资源。候选只接收单题文件；代码题交实际源文件、科学报告和有断言的独立测试，科研题交题目列出的精确文件。文件路径、伪代码、截图或“已生成”的承诺不能代替文件字节。

论文材料是三篇真实开放文章，合计十七幅主图。P1 为 Weissgerber 等的 *Beyond Bar and Line Graphs*，P2 为 Rougier 等的 *Ten Simple Rules for Better Figures*，P3 为 Crameri 等的 *The misuse of colour in science communication*。指定完整主文、参考文献与主图可离线阅读，P1 另有完整 S1 Text 方法／结果提取；未给定的其他 SI 和外链脚本明确不在已读／复现范围。P1/P3 为逐篇核验的 CC BY 4.0，P2 为其文章明确声明的 CC0，而不是套用出版商通常许可。

显示图经有说明的降采样和颜色量化，保留科学内容与完整图注，单题 HTML 小于 3 MB。原图高分辨率重复字节省略后，仍保留原始检索 URL、大小、SHA-256 以及全部所需显示资产；原文 XML/HTML/DOCX 保留。方法与许可详情见 [来源说明](../../sources/v1/README.md) 和 [manifest](../../sources/v1/manifest.json)。这些不是只有链接的“阅读清单”，也不是用来源摘要冒充全文。

### 3.2 可选模态具有独立分母

| 集合 | 主要产物 | 评价方式 |
| --- | --- | --- |
| C01–C10 | 8 题 Python、2 题 Fortran 源码，报告，独立测试 | 自动 70 分加独立质量 30 分；核心责任另列。 |
| R01–R06 | SVG、Python 图、保真编辑、结果／讨论、精读复现、小综述 | 每题五个锚定人工维度，共 100 分；核心责任另列。 |
| X01 | 真正离线可交互 HTML | 科学语义、控件行为、可达性、自包含实现及实际验证。 |
| X02 | 实际视频、同步字幕、源项目和场景证据 | 科学叙事、实际画面、节奏、字幕、署名及媒体核验。 |
| X03 | 实际原创器乐音频、可编辑源项目和测量记录 | 原创作曲、旁白语境、音频完整性、再生成和来源。 |

不能生成或观察某种可选模态时，记录具体 `unavailable` 原因，在事先声明的启用集合外保留未评；不能静默记零、默认通过，或让文字计划代替实际声音／视频。若已启用且具备条件，却漏交必需文件，应按已观察的缺交处理。可选编码器或某个响度工具缺失，不一定等于没有音频生产能力，应报告准确缺口。

## 4. 十道代码题的能力矩阵与科学边界

难度是 **1–5 的设计先验**，尚未用真实模型通过率标定。建议作答时间与评分器运行超时是不同变量；尤其 C06–C10 的 30/40/40/60/75 分钟是候选工作预算，不能误读为参考程序运行秒数。实际可用库、参数域和接口以冻结单题为准。

| 题号 | 语言／先验难度／作答分钟 | 主要责任 | 应采用的独立核验 | 明确边界 |
| --- | --- | --- | --- | --- |
| C01 | Python／1／15 | 仪器 CSV 身份、最后可用重复记录、温度和标准不确定度换算、逆方差汇总 | 不等权两点解析计算、缺失／拒绝行顺序、极小误差与输入不变性 | 已知独立标准误差；不含相关校准漂移，不能把温标偏移加到 sigma。 |
| C02 | Python／2／15 | 组内技术重复、层内／层间等权目标、确定性分层组 bootstrap | 手工随机流重放、单组分布、行置换、不平衡重复反例 | 区间以观测组为条件；更多 bootstrap 不创造独立组，非正比例不是严格检验 p 值。 |
| C03 | Python／3／15 | 修复非均匀有限体积后向 Euler 导热，多处缺陷和能量收支 | 两单元模态解析、绝热能量不变量、源／边界积分、单单元双边界 | 核验给定离散模型；不由离散真值推出连续 PDE 收敛，短运行也不能证明渐近复杂度。 |
| C04 | Python／4／30 | 被动相干多层复光学、s/p 切向电场约定、稳定组合与功率归一化 | 独立特征矩阵、单界面 Fresnel、无损守恒、全反射与厚吸收极限 | 各向同性非磁相干膜、无损半空间；不含增益、非相干平均或精确临界奇点。 |
| C05 | Python／5／30 | 规定自适应刚性算法、拒步回滚、右连续源切换、局部时钟与硬停点 | 交换指数解、分段源解析、守恒／平衡态、时间平移关系 | 测指定控制器实施而非发现新积分法；步数有合同，局部容差不是全局误差证书。 |
| C06 | Fortran／3／30 | 非均匀网格 SG 输运通量、漂移号、源损体积分、小／大 Peclet 稳定性 | 非均匀指数精确解、积分源损收支、Boltzmann 零流 | 有界一维线性经典合成输运；不是完整多物理器件模拟。 |
| C07 | Python／4／40 | 共同扩散参数、独立消除各实验振幅与基线、异方差绝对误差、剖面区间与投影信息 | 无噪声回收、sigma 整体缩放、剖面曲率与 Schur 补、结构平坦情形 | 有限非平坦测试族；指定似然比区间不保证精确有限样本覆盖，局部信息与完整区间不同。 |
| C08 | Python／4／40 | 二维非均匀异质、对角各向异性装配，谐均面系数和外向积分流 | 仿射解、独立连续正弦制造解及网格细化、全局源流平衡、忽略内部边界占位值 | 只含与坐标对齐的正对角张量；流围绕内部控制体并集，不是另行假定的连续外边界重建。 |
| C09 | Fortran／5／60 | 同时求解单载流子 SG／Poisson 非线性残差，正密度、全局化与规范约定 | 独立重算两组原始残差、带流制造解、Boltzmann 平衡、势平移 | 有限、具有已知正解的稳态测试族；不宣称一般全局唯一，不含复合、隧穿或额外载流子。 |
| C10 | Python／5／75 | 修复反应扩散、离散切线、绝对 sigma 双参数反演、完整检查点和确定性参数自举 | 纯反应递推、Fourier 离散放大、中心差分切线、独立模态反演、JSON 重启身份 | 小规模指定后向 Euler 流水线；不以连续解替代离散导数，有限自举不保证精确覆盖。 |

这一梯度同时包含从头实现与修复、线性与非线性、正向与逆向、空间与时间、随机与确定性状态。C04 刻意只给物理边界和相位定义，不直接给稳定层组合递推，要求候选推导或选择适当数值表示；C05 则明确规定控制器，因为计数本身是输出合同。两题难度来源不同，不能只凭公式长短排列。

## 5. 独立测试怎样避免“程序证明自己”

参考程序和候选程序对同一输入相等，是必要但不充分的证据：两者可能共享符号、边界或单位错误。因此检验同时使用解析关系、物理不变量、与生产装配不同来源的制造解、变形关系和独立残差重算。C03 的两单元模态不同于照抄三对角装配；C04 的独立特征矩阵只用于适合的有限参数核对，不能用其溢出的厚吸收输出反过来否定稳定算法；C08 将离散制造解与连续网格细化分开，避免循环真值。

C07 检查消去 nuisance 后的信息，而非把未知振幅／基线当成固定值；C10 核对离散时间步的切线，而非拿连续时间导数充当替代。C09 不能靠自报一个小 `residual_inf` 获分，评分端重算原始方程、接触边界、正性和 SG 流；在不声称唯一性的有界族内，满足合同的任一正解都可接受。Fortran 题需实际编译运行，读取源码或找到某个语法标记不算数值验收。

候选自己的 `tests.py` 也必须有断言和独立关系，报告说明真实执行过什么、未执行什么。只回调同一函数生成“真值”、只断言能运行或把参数差异全交给宽松 `isclose`，不能提供同等验证。参考程序通过有限集，不证明整个连续参数域正确，也不自动给参考报告人工满分。具体推导、执行与边界见 [Python 数值说明](../v1-python-notes.md)、[进阶数值说明](../v1-advanced-notes.md) 和 [验证记录](validation.md)。

## 6. 分数、核心责任与人工能力画像

代码自动分固定为 **基础 20、科学正确性 30、压力／边界 20**，共 70。基础检查覆盖接口和简单极限；科学检查覆盖容易被“能跑”掩盖的模型、统计和守恒语义；压力项覆盖合理域内数值稳定性、非均匀输入和非法输入。它们不是三种候选可自行挑选的难度，也不应由题目测试用例数量决定权重。

代码另有 30 分独立质量：科学解释与验证范围、独立测试与复现、实现与交接各 10 分。每维按 0–4 整数等级乘权重／4计分，0/2/4 有锚点，1/3 需说明中间表现。未阅报告、缺运行条件或没有观察所需成果时保留 `null`／未评，不能预填 0 或 30。完整总分只有在必需自动评分覆盖和独立评阅具备后才形成。

核心责任用 `pass/fail/unassessed` 另外记录。高分不补偿关键科学失败或必需成果缺失，原始分也不被暗中清零。操作性合格门槛同时要求完成及达到预设总分阈值；现有 80 分属于待经验校准的操作标准，不是自然科学分界。评分应并列展示原始分、关键失败、待评事项和覆盖，避免把“80 但核心失败”变成能力通过。

R/X 采用五个与任务直接相关的人工维度，每题 100 分，而非机械套 70+30。R01 检查真实参考学习与可编辑图；R02 检查逐轴判断；R03 检查自然英语与事实台账；R04 检查图—数—论证；R05 检查阅读逻辑与部分复现；R06 检查跨来源综合和跨产物一致性。它们有相应核心责任，不能以统一的“写得漂亮”总印象评分。全部精确权重、锚点和交付规则见 [科研指南](research-guide.md)。

人工画像还需要真实感知证据。观察记录绑定文件名、SHA-256、指定 `viewed/watched/listened/interacted` 动作、执行状态及具体发现；SVG 必须看，HTML 必须操作，视频必须看，音频必须听。哈希保证台账对应的是这些字节，不能证明人真实观看。LLM 评阅记录模型与提示身份，完成权限为 `llm_provisional`；不能冒充人类结论，也不应把两类评阅混成一个均分队列。

## 7. 已执行的 28 个错误控制说明什么

仓库已对十个参考实现和 **28 个可执行错误实现**做实际评分路径检查。下表来自 seed 17 的 trusted subprocess 记录及数值说明，分数均为自动分／70。错误实现是真实改错的候选程序，不是评测器读一个标签便返回预定分数。完整命令、运行后端、可重现记录与当前版本状态仍以 [验证记录](validation.md) 为准。

| 题号 | 实际错误控制及对应自动分 |
| --- | --- |
| C01 | 首条重复胜出 55；用等权替代逆方差 18。 |
| C02 | 技术重复伪独立 45；按组数合并层 40。 |
| C03 | 算术界面系数 40；单单元遗漏左边界 60。 |
| C04 | 振幅平方冒充功率透射 25；忽略 p 偏振 39；任意厚度截断 29。 |
| C05 | 提交被拒状态 33；源切换采用左连续 55；丢弃小末端区间 48。 |
| C06 | 中心漂移 32；统一控制体宽度 60；右边界系数错误 32。 |
| C07 | 丢基线 6；忽略异方差权重 13；使用条件信息 13。 |
| C08 | 算术界面 46；交换张量方向 26；反转西侧通量 6。 |
| C09 | Poisson 网格尺度错误 32；重设势规范 32；漂移号反转 22。 |
| C10 | 反应转移滞后一层 14；重置检查点切线 39；残差缩放协方差 50；重复使用自举噪声 60。 |

这些结果说明已知科学错误能够损失相应分数，同时保留部分正确行为的梯度。十个参考实现的自动 70 分只说明它们满足当前测试，不提供人工 30 分。28 个控制也不是 28 个模型，不是自然失败分布，更不是对真实模型的排序或置信区间。围绕作者已知错误设计的测试可能漏掉完全不同的错误路径；高分错误控制仍需由核心检查和人工解释揭示实质失误。

trusted 后端用于仓库可信控制，不证明恶意外部程序已被隔离，也不认证 Docker 网络／文件系统边界。正式外部候选应在已验证、固定镜像和权限的执行环境中评分。缺编译器、容器或评阅工具要报告基础设施未评，不能把它当候选科学失败。当前容器与集成的真实验证状态由验证页更新，本报告不把历史绿灯写成未来所有环境的保证。

## 8. 公开评测的隔离与答案访问边界

正式作答应在全新会话／新环境，仅提供冻结候选单文件，不挂载评分仓库、参考实现、期望结果、旧运行日志或其他候选成果。评分在另一环境进行；执行载荷只给输入与候选源文件，不把 expected 值送入候选工作进程。公开样例说明合同，不附正确输出。题包、提交、量表、执行报告和评阅文件的身份需要绑定，字节改变后不能套用旧审阅。

必须如实区分“候选看不见”与“公众不能看见”。这是开放仓库：所谓隐藏检查，是相对本次正式候选上下文和 worker 载荷的隔离，评测源码和期望生成方法对仓库读者仍然可见。公开 seed 可复现和改变合理参数，减少只记住某个样例的作用；它不是秘密，也没有增加新的科学任务家族。公开题目、方法或参考解可能进入训练数据，强隔离与新会话不能保证训练污染不存在。

因此可信主张是“此次运行按声明隔离了答案材料，并保存可审计证据”，不能声称“绝无泄漏或污染”。有条件时可由未参与调参的维护者在冻结合同域内保管独立留出实例，并区分开发与最终评价；新实例仍需独立科学校核。不要让候选自行修改评分器、把针对本题的答案程序塞进 skill，或反复观察最终测试后把适配进步称为模型泛化。

## 9. 真实模型校准与配对比较计划

### 9.1 先定义测量单位和完成事件

主要单位是任务家族，C 有十个、R 有六个；一个 seed 是同一家族的参数实例，一次新会话是同一条件下的重复尝试。增加 seed 或重跑可以估计实例敏感性和随机性，不能把十个家族宣传成数百个独立科学问题。R 的闭合材料在当前版本不随 seed 创造新论文集，也不应把相同题包重复导出当成新阅读任务。

预先定义并分别报告自动得分、完整总分、核心完成率和操作性合格率，写明分母与未评规则。每题保留分层／分维分布、主要失败类型、时间和成本。不能把 70 自动分归一化后称为完整科研质量，也不能将未评任务从必做分母删除来提高总分。可选集合按可用模态另报，比较不同配置时使用声明的共同集合。

### 9.2 诊断天花板、地板和真正区分来源

先做小规模覆盖性试跑，再冻结正式比较方案。若某题在不同配置上几乎总成功，检查是否只测了基本库调用、题面过度给出实现、样例被硬编码，或核心责任太弱；若几乎总失败，先检查合同歧义、预算、依赖和错误判据，再考虑是否科学要求过高。通过率天花板／地板是诊断，不自动意味着应该改分数。

同时看 B/scientific 和 C/stress 的失败位置、人工维度分散程度、核心责任、文件与执行覆盖。一个总分饱和但仍在方法解释、成本或完成率上有差异的任务，可能仍有用途；一个所有人失败但主要因编译器缺失的任务没有测到科学能力。难度标签应根据这些证据更新为经验描述，并记录估计不确定性，不能凭一两次输出给前沿模型贴稳定等级。

修题与最终排名应分开。开发试跑发现问题后版本化，重新导出并让所有比较对象重跑；不能只对某模型追加有利案例。冻结后若发现评分缺陷，报告影响、修复与统一重评，而非在旧报告上补一个新身份。

### 9.3 重复运行采用配对设计

同一配置使用相同家族、实例 seed 集合和预先规定次数的新会话；不同模型／harness 使用同一集合、相同完成规则和预算。模型采样 seed、数据 seed 与重复编号分别保存；provider 不支持或不能保证 seed 重现时如实标记。平衡运行顺序并固定硬件／队列条件，避免把资源差异误认成模型差异。

比较先在相同家族—实例—重复条件下计算配对差，再按家族等权汇总；可用尊重家族／实例层级的重采样或区间，并同时展示每题原始结果和失败谱。家族很少时区间稳定性有限，应避免从小样本得出很宽泛的模型总体结论。不能把所有测试用例、seed 和重跑当独立样本来制造很窄误差条，也不能挑最好一次替代预定全部尝试。

人类评分建议独立双评、匿名模型身份、保留原始评分与裁决；报告分歧、逐维理由及未观察覆盖。一次 LLM 判断不是人工一致性证据。质量评阅、科学门槛和自动执行的差异应保留，而不是压成一个无法解释的总榜。

### 9.4 区分基础模型与工具系统

“模型版本”不足以定义一次实验。固定输入、无执行工具的轨道，测指定提示／预算下生成答案与代码的能力；带执行、浏览、skills、多 agent、自动恢复的轨道，测模型加 harness 的系统能力。后者得到更好结果，可以归因于声明条件下的整体系统，不应直接写成基础模型本身提升。

配对消融每次只改变一个预先声明因素：相同模型、题目、预算和 harness 下比较无 skill／固定公开 skill，或无执行／有执行。保存 skill 内容身份、工具版本、系统提示、上下文／压缩策略、重试规则、wall time、输出／推理预算和费用口径。无法记录的 token、费用或采样配置保持未知，不能写零。候选可用作答预算与提交代码运行超时分别记录；额外人工修复或评阅返工也要单列，避免“同预算”只是名称相同。

## 10. 从 V0.2 到 V1 的实际迁移

V1 作为并行新协议接入，不改写旧 `nrb` 结果的含义。旧任务与验证仍可用于历史复现；新实验通过 `python -m nrb_v1`／`nrb-v1` 导出、评分和创建评阅包。C/R/X ID 不映射为旧 NRB 分数，新的必做集合是十 C 加六 R，可选集合独立。历史 harness 适配也不能因为入口名字相似就假定完整覆盖新模态与提交格式，应按 V1 合同验证。

建议迁移顺序是先冻结一个 V1 代码身份与执行配置，完成参考／错误控制、独立数值和基础设施检查；再导出候选目录，检查单题打开与材料可见性；最后安排真实模型试跑及独立评阅。正式记录同时绑定任务包、提交、量表和评分器内容；当前源码仍在变化时，报告保留待定，不写死某个提交哈希或从旧验证挪用通过状态。

交付上，必需产物全部使用规范确切文件名。自然编辑器项目、视频渲染项目或 MIDI／合成源可以装入 `source.zip`，内含本地说明；X02 固定 `captions.srt`；X03 的 MP3 仅为可选预览。候选只拿一份单题材料不意味着可以只交一个最终截图，交付合同仍需源、数据、报告和观察所需媒体。细节见 [科研指南](research-guide.md) 与相应单题。

后续发布能够支持的结论，应随实际证据逐步增加：先是“材料自包含、参考与已知错误控制经过执行”，随后是“若干明确配置已有重复实测与盲评”，再讨论“在这些家族和条件上的稳定差异”。本版不提前填充真实模型成绩，不把脚本自检写成研究能力排名，也不承诺公开基准永远没有训练污染。
